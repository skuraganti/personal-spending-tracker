# Engineering decisions and experiments

Actual development date: 2026-10-16.

- **Data:** compared original MoneyVis, UCI Online Retail and PKDD1999 Financial. MoneyVis matches the actual statement workflow. Its standalone data license remains unspecified; express author research/education release supports this private local demo. No data redistribution is claimed. Article license and data permissions are separate.
- **Money:** integer pennies with Decimal validation at input; no floating-point accumulation. GBP is an explicit assumption because the raw file has no currency column. Credits are not negative spending, and savings/transfer flows need separate explanation.
- **Privacy:** keep source/cache/database excluded. The lead-owned preparation script masks 668 rows in transfer/income/deposit/cheque types, preserving all dates, amounts, ordering and counts. This sacrifices counterparty detail; these masked labels must not become recurring-merchant evidence. The source data may retain residual identifying detail, so masking is not an anonymity guarantee. Public Pages uses only an independent synthetic fixture; no real transaction data is redistributed.
- **Storage:** SQLite suits one local reviewer and transactional import. A separate server database would add a service and resource cost without a demonstrated need. WAL/transactions/constraints and restart checks remain necessary.
- **UI:** native browser HTML/CSS/JS keeps dependencies and containers small. Charts must have textual equivalents, controls must be keyboard accessible and source dates visible. Avoid fabricated empty-state metrics.
- **Inference:** recurrence is a rule-based hypothesis supported by distinct dates, cadence and amount stability. It cannot establish an actual obligation or an active subscription in 2026 from records ending in 2022.
- **Isolation:** project source/cache/lock/config/tests/Compose volume/network/port are independent. Use an existing Docker engine without changing unrelated services. Public source and the synthetic Pages demo are separate from excluded local data.

- **Observed Docker correction:** the first healthy container had HostConfig port bindings but NetworkSettings.Ports was null on the internal bridge; Mac HTTP/browser connections were refused. Recreated only this project's network/container, preserving the named volume, using a normal separate bridge and explicit 127.0.0.1 publication. The app has no external service integration or telemetry exporter. This is local port access plus project network isolation, not an operating-system egress firewall.
- **Spending semantics correction:** FPO/FPI identifies bank-transfer mechanics, not ownership or purpose. Default these to “Unreviewed transfers”; outbound amounts count as spending until reviewed, so rent-like payments are not silently excluded. Only Savings/explicit Transfers categories are excluded. Schema v2 migrates only untouched original defaults, preserving user edits and manual overrides.
- **Observed browser automation correction:** agent-browser text filling cleared the native month input, so form validation correctly prevented saving. The browser verification uses the native value setter for that picker only and real UI interactions for other controls; this is documented rather than treated as a product failure.

- **Independent review and accessibility fixes:** a reviewer identified a false rollback message if import committed but a later refresh failed. The UI now preserves the receipt and distinguishes refresh failure; a real browser import with a synthetic post-commit metadata failure passed. The full overview accessibility scan found two low-contrast captions (3.9:1); their colour was darkened. The labeled cashflow wrapper gained an explicit group role. Decorative navigation glyphs are redundant with visible link text and were manually inspected.
